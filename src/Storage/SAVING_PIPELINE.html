Saving and migrating, the whole pipeline

One page to hold the system in mind at once: where a save goes, what every table holds, and a step by step run of one schema change on a live site. Built from PROPOSAL_FOR_SAVING.md as of stage 4 (the fixup language).

Built: stages 1 to 3 Planned: stage 4 on n = open point in the proposal

1. The map

Two lanes. Schema changes only ever append to the history, and the stored schemas are its newest version. Everything that reads or writes content runs through one translator, which moves values between versions. Solid boxes exist in code, dashed boxes are planned, and red badges are open points. During the simulation below, the boxes it touches light up.

2. Step by step: retyping cabins on a live site

Three yachts are stored. An admin changes cabins from a number to text and, in the same save, creates a fourth yacht that already uses text. Watch the tables change. Use the buttons or the arrow keys.

3. One translator, six uses

Stage 4 makes every fixup a piece of stored JSON in the history, the one source of truth. The translator moves values between any two versions through it, and each of these is the translator called with a different start and end.
